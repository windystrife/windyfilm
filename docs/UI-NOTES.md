## Design

**Palette 0x50..0xFE (175 entries).**
- Why this range:
  - ML draws only with 0..0x4F (COLOR_GRAY tops out at 0x4F);
  - 0xFF is Canon's ClearScreen;
  - entry 0 is transparent.
- Layout (offsets from 0x50):

  | entries | offsets | content |
  |---|---|---|
  | 21 | 0..20 | fixed UI colours (`fixed_rgb` in wf_gfx.c) |
  | 6 | 21..26 | background refs, ordered-dithered between them |
  | 33 | 27..59 | glow: 3 background refs (y 0 / 150 / 300) x 11 rings, ring and ref dithered |
  | 12 | 60..71 | floor shadow: 4 rings x 3 levels |
  | 103 | 72..174 | can colours |

- The glow is recoloured per film by rewriting only its 33 + 12 entries (`wfp_set_glow`).
- Entry values:
  - format `(op << 24) | (Y << 16) | (U << 8) | V`, BT.601;
  - scaled into the Y range between Canon's own black (2) and white (1) entries;
  - opacity taken from Canon's white.
- Written to both register banks (`LCD_Palette[3i]`, `[3i + 0x300]`).
- Restored on close from `LCD_Palette[3i + 2]`.
- Keep-alive:
  - every 100 ms, 5 entries are probed with `shamem_read`, and all entries are rewritten if one changed;
  - all entries are force-rewritten every 2 s.
  - ML's `bmp_on()` writes Canon's 256 values back, and `bmp_off()` makes them all transparent.

**UI task.**
- `wf_ui_open()` (from the GUI task on the open key, or from wf_task after the menu entry) claims the open under `cli`
  and only starts the task "wf_ui" (prio 0x1B: above the film worker 0x1C, which starved the old 0x1E task for the
  seconds of a shot's develop; 8 KB stack). A failed `task_create` leaves it closed.
- The task beats (`hb`, `phase`) at every step. `wf_ui_key()` passes a key on and asks the task to close when there was
  no beat for 2 s (log `ui: no beat for N ms (state S, phase P)`, phases at the top of wf_ui.c); the task is never
  declared closed from outside, it gives the screen back when it runs.
- On start, the task:
  - stops the ML menu if it is shown;
  - builds the list (ready films, by group then `order`);
  - opens both packs;
  - 5D2: asks Canon for a dialog under the browser (mode 2 without LV, 38 in LV with the bitmap muted; none while
    recording; DESIGN 5);
  - calls `canon_gui_disable_front_buffer()`, which is the EOS M patch 0003 screen take and may sleep up to about 480 ms;
  - takes the palette.
- SET that loads a film: the load animation (`wfui_render_anim`, ~1.15 s, only its panel is drawn again per frame),
  then close; 5D2 opened without LV: `force_liveview()` after the screen is Canon's (state CLOSING: keys pass on).
- Every 20 ms it:
  - handles the queued keys;
  - checks `wf_gen()`;
  - renders the whole browser into the idle buffer, then `bmp_idle_copy(1, 0)`, when something changed;
  - also renders once every 1 s, because Canon may draw into the idle buffer and ML (5D2 global draw) into the front one.
- On close, in order:
  - zero the screen;
  - restore the palette;
  - call `canon_gui_enable_front_buffer(1)`;
  - free everything.
- `wf_ui_close()` asks the task to stop and waits up to 2 s; call it from a task that can sleep.
- `wf_ui_key()` (GUI task) never blocks: it queues 16 keys.

**Keys.**

| key | action | EOS M | 5D2 |
|---|---|---|---|
| PRESS_LEFT / RIGHT | film, across groups (5D2 editing: row value) | arrows | joystick |
| PRESS_UP / DOWN | row (wraps) | arrows | joystick |
| WHEEL_LEFT / RIGHT | focused row value -1 / +1 | rear ring | top dial (in LV only under mode 38) |
| WHEEL_UP / DOWN | focused row value -1 / +1 | - | rear wheel (in LV only under mode 38) |
| PRESS_SET | load (`wf_load`), then the animation and close | ring centre (patch 0002) | SET |
| JOY_CENTER | EOS M: load; 5D2: edit the focused row on / off | | joystick press |
| Q / PICSTYLE / TOUCH_1_FINGER | next group (selection kept per group) | 1-finger tap | Pict.Style |
| INFO | overlay on / off | INFO | INFO |
| MENU / TRASH / PLAY / LV | close (consumed) | MENU, 2-finger tap (patch: MENU) | MENU, TRASH |
| half / full shutter, REC | close and pass on | | |

- Every other key is consumed while the browser is open.
- Open key (`wf_ui_open_key`):
  - fires on MODULE_KEY_TRASH, with no ML menu and gui_state IDLE;
  - on EOS M, long DOWN arrives as TRASH (patch 0002), and it also needs stills LiveView (Canon's LV Set dialog only
    comes up there);
  - on 5D2, it fires on TRASH anywhere outside playback; the browser first asks Canon for GUI mode 2 without LiveView
    (display on) or 38 in LiveView (dials), as ML's menu (DESIGN 5), mode 0 again on close.
- Every key passes on while no beat came for 2 s, and while the task starts LiveView after a load (CLOSING).

**Strip.**
- 11 slots, `x = -20 + 72 i`.
- The selection stays in slots 1..8 (slot 0 and 9..10 are under the fades).
- First open of a group puts the selection in slot 4.
- The strip shows the current group.
- L / R at a group end moves into the next group.
- The scrollbar shows the strip window in the whole list (52).

**Text.**
- Own pack:
  - 26.6 advances from unhinted `getlength`, plus kerning (`getlength(ab) - getlength(a) - getlength(b)`);
  - glyphs drawn at `((pen + 32) >> 6) + x`, pixel-identical to PIL's mono rendering of the mockup.
- Fallbacks:
  - no ML argnor23 / argnor28 → own 15 px;
  - no own pack → ML term12.

## What the core must provide or guarantee

- `wf_card_read`: 0 = ok, `*size` = the file size, a short read is an error. This is how wf_main.c does it today.
- `wf_ui_key` gets every key while `wf_ui_is_open()`, and `wf_ui_open_key` only when closed. wf_main.c already does
  this.
- EOS M card core with patches 0002 (offer DOWN / SET before the long-press logic, long DOWN → TRASH) and 0003
  (module screen take, 2-finger tap → MENU with a 3 s close window, `_redraw_do` skipped while a module owns the
  screen).
- `wf_ui_close()` only from a task that may sleep (module deinit is fine).
- `wf_load` / `wf_row_step` callable from the UI task (they run there, not in the GUI task).
- `wf_gen()` bumped on every change the browser shows: loaded film, row values, availability, status.
- `film->can` = the entry in WFCANS.DAT. The UI checks the id and searches the index when they differ. 255 = plain can.

## Traps

- The card `.sym` files have CRLF line endings: `tr -d '\r'` before grep.
- ML's `module.h` with `-DMODULE` includes `build/module_strings.h`. The module build generates it; armcheck makes an
  empty stub.
- PIL 10 with raqm draws text at fractional, unhinted advances with kerning. Measuring single glyphs gives ±1 px
  vertical quirks, so capture glyphs fenced between `"| "` and `" |"` at a whole-pixel pen.
- Glow LUT index: `d2 * 746 >> 16` reached 256 at the circle edge (found by ASan); 745 keeps it < 256.
- ML `bmp_off()` / `bmp_on()` rewrite all 256 palette entries. That is why the palette keep-alive exists.
- 5D2: PicStyle becomes Q only inside the ML menu. Outside it arrives once, as MODULE_KEY_PICSTYLE.
- Never run `gen_cans_real.py main()` (it reads the old pack's palette). Never read filmroll.mo or FILMCAN.DAT.

## Open risks on the camera

- The palette format and opacity are assumed from ML's code: Y range from Canon's black / white entries, opacity from
  white. Check the colours against the PNGs. Check that the browser covers LiveView fully, with no see-through.
- 5D2 has no screen-take patch, so ML global draw (zebras, cropmarks) or a Canon / ML `redraw()` can show for up to
  1 s, until the next full render.
- On EOS M, outside stills LV (movie mode), patch 0003 does not raise Canon's dialog. The arrows may then arrive as
  Canon's generic code. The open key refuses there; the menu entry still opens the browser.
- First paint reads about 12 can images (open / seek / read / close each). Each L / R reads 2-3 new images, so expect
  tens of ms per step.
- If the display is off at close, Canon's entries are not written back (the palette write is skipped).
